## Binary Circle artifact, version 2

`Circle --ginkgo` produces one self-contained binary package. No JSON manifest
or source-information file is required to interpret its execution metadata.
This format is still under development and may change without a version bump.
All literals are loaded through the typed constant pool. Version 2 replaces the
draft version 1 JSON representation. The existing Rust executor does not yet
execute Ginkgo packages.

The section order follows the original package layout: magic and descriptor,
symbol table, constant table, then instructions. Integers are little-endian,
booleans occupy one byte, and symbol IDs and collection counts are `u32`.
Byte lengths remain `u64`; function code offsets, code lengths, and register
counts remain `i64`. Records are packed without padding. Strings are UTF-8.

| Section | Encoding |
| --- | --- |
| Magic | Eight bytes: ASCII `GINKGO` followed by two zero bytes |
| Format version | `u32`, currently 2 |
| Package descriptor | Fields below; entrypoint ID is `u32` |
| Symbol table | `u32` count followed by symbol records |
| Constant pools | `u32` pool count followed by each counted constant table |
| Instructions | All remaining bytes; functions are concatenated in symbol-ID order |

## Package descriptor

The descriptor follows the original field order, with a 32-bit entrypoint ID.
Its fields, in order, are package
type (`u8`: 0 library, 1 executable), name (`u64` byte length and UTF-8 bytes),
package version (`i64`), entrypoint function ID (`u32`), data alignment length
(`u64`), root function table position (`u64`), root constant table position
(`u64`), root group table position (`u64`), and region table position (`u64`).
The last four positions are reserved and zero in Circle's default descriptor;
tables are read sequentially. The alignment field does not introduce padding.
The legacy descriptor retains its 64-bit entrypoint ID. The package version is
independent of the binary format version. The entrypoint is zero for libraries.

## Symbol table

Each record starts with a `u32` symbol ID and `u8` kind, followed immediately by
the payload below. Kind numbers match the original instruction set's symbol
tags. Names, signatures, parameter names, source paths, and the compiler's
scope tree are omitted from execution records.

An ID list is a `u32` count followed by `u32` IDs. Collection counts and IDs
range from 0 to 4,294,967,295; encoding rejects values that exceed `u32`.
A declaration consists of
dimension (`i32`), mutability (`u8`: 0 constant, 1 variable), type symbol ID
(`u32`), and allow-none (`bool`).

| Kind | Payload, in order |
| --- | --- |
| `0x01` Namespace | Empty |
| `0x02` Function | Code offset (`i64`), byte length (`i64`), return declaration, parameter count (`u32`) and declarations, annotation ID list, generic type ID list, register count (`i64`), constant pool index (`u32`) |
| `0x03` Group field | Declaration |
| `0x04` Data type | Category (`u8`: 0 internal, 1 user-defined), then group or enum ID (`u32`) only for user-defined types |
| `0x06` Group | Field ID list, lifecycle count (`u32`) and pairs of stage (`u8`) and function ID (`u32`), function ID list, subgroup ID list, annotation ID list, generic type ID list, derivation type ID list |
| `0x07` Annotation | Target group ID (`u32`) |
| `0x08` Enum | Annotation ID list, member ID list |
| `0x09` Enum member | Annotation ID list |
| `0x0a` Generic type parameter | Constraint type ID (`u32`) |

Function offsets are relative to the instruction section. Jumps remain local
to their owning function. External declarations have zero byte length. Only
generated functions and explicit external declarations have function records;
unused deferred standard-library bodies are not emitted.

## Constant pools

Pools retain compilation-unit order. Each pool starts with a `u32` constant
count. Its records follow the original constant descriptor structure with
32-bit IDs: local index (`u32`), type symbol ID (`u32`), is-array (`bool`, currently
false), payload byte length (`u64`), and payload bytes. `ld` uses its
function's pool index and a local constant index; pool and constant indices
start at zero. Unit names are not stored.

| Value | Payload |
| --- | --- |
| Integer | Signed `i64` |
| Decimal | 8-byte IEEE 754 binary64 (`double`) |
| Boolean | One byte, 0 or 1 |
| String | UTF-8 bytes; length is the descriptor's payload byte length |
| None | Empty payload |

Decimal source values are converted to doubles when the package is encoded.
Strings use byte lengths, including non-ASCII text.
All literals, including integers, are interned by type and value within each
compilation unit. Functions in that unit share its pool.

## Optional debugging information

`--source-info <path>` writes a separate JSON file containing `instructionSet`
(`"arc-ginkgo"`), `symbolMapping` (numeric IDs to readable signatures), and
`functionSources` (function IDs to source paths). It is solely for descriptions
and debugging tools such as cmdec; removing it does not change the package's
execution data. Instruction-level source mapping is not implemented. See
[Compiler support](/ginkgo/implementation) for current runtime and lowering limits.
