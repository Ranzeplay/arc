---
title: 'Draft binary encoding'
---

This page defines the current compiler's draft wire convention for the
[Ginkgo instruction set](/ginkgo/instructions). It supplements the instruction
semantics; it is not a finalized runtime ABI. Runtime cmdec decodes these
instructions; the executor still supports only the legacy instruction set.

Each instruction starts with its one-byte opcode, followed by operands in the
order shown on its instruction page. There is no padding. Multi-byte values use
little-endian byte order. A `flags` operand is always present where shown, even
when its value is zero.

| Operand | Encoding |
| --- | --- |
| Register (`src`, `dest`, `condition`, `amount`, arguments, return value) | Unsigned 16-bit |
| Dimension (`dim`) | Unsigned 16-bit |
| Function, type or field symbol ID | Unsigned 32-bit |
| Constant entry index (`ld`) | Unsigned 32-bit |
| Jump target | Signed 64-bit function-local byte address |
| Flags | Unsigned 8-bit |

Symbol operands are IDs, not positions in the serialized symbol table. Constant
indices address the unit pool selected by the function's `ConstantPool` metadata.
They are local to that pool and cannot select another pool.
All literals use typed constants: integers have signed 64-bit payloads and
decimals have IEEE 754 binary64 payloads. The current draft uses a single `ld` opcode
(`0x1C`); the former immediate-load opcodes `0x1D` and `0x1E` are unassigned.

The [package metadata](/ginkgo/descriptors/pkg) also uses unsigned 32-bit
entrypoint function IDs, table counts, and ID-list lengths.

## Flag bits

Bit 0 is the least significant bit. Unlisted bits are reserved and emitted as zero.
Last-use and destination-usage flags are optimization hints. `usage_hint` and
`use_dest_next` both describe use of the destination immediately after definition.

| Instructions | Bit 0 | Bit 1 | Bit 2 | Bit 3 | Bit 4 |
| --- | --- | --- | --- | --- | --- |
| `add`, `sub`, `mul`, `div`, `mod`, `bitand`, `bitor`, `bitxor`, `logand`, `logor`, `logxor` | `last_use_src_a` | `last_use_src_b` | `use_dest_next` | — | — |
| `lsa`, `rsa`, `rsl` | `last_use_src` | `last_use_amount` | `use_dest_next` | — | — |
| `inv`, `bitnot`, `lognot` | `last_use_src` | `use_dest_next` | — | — | — |
| `copy`, `clone`, `ref` | `last_use_src` | `usage_hint` | — | — | — |
| `eq`, `neq`, `lt`, `le`, `gt`, `ge` | `last_use_src_l` | `last_use_src_r` | `use_dest_next` | `cmp_ref` | — |
| `cjp` | `cond_true` | `cond_false` | `cond_not_none` | `cond_none` | `last_use_condition` |
| `arg` | `last_use` | — | — | — | — |
| `invoke` | `is_virt` | — | — | — | — |
| `retv`, `retn` | `expect_return_value` (ERV) | — | — | — | — |
| `ld` | `load_ref` | `usage_hint` | — | — | — |
| `init_obj` | `usage_hint` | — | — | — | — |
| `ld_field`, `st_field` | `last_use_src` | `usage_hint` | — | — | — |

All comparison models expose bit 3. The compiler only sets `cmp_ref` for equality
and inequality; reference ordering has no defined runtime contract and must not
be inferred from the availability of that bit. Conditional jumps generated by
the compiler select exactly one condition; combinations of condition bits are
not yet specified.

`nop`, `lbl`, `jmp`, and `pcall` have no flag byte.

## Encoded lengths

Lengths include the opcode and all operands, in bytes.

| Instructions | Length |
| --- | ---: |
| `nop`, `lbl` | 1 |
| `retn` | 2 |
| `arg`, `retv`, `invoke` | 4 |
| `pcall` | 5 |
| `inv`, `bitnot`, `lognot`, `copy`, `clone`, `ref` | 6 |
| Binary arithmetic, shifts, binary logical, all comparisons, `ld` | 8 |
| `jmp` | 9 |
| `init_obj`, `ld_field`, `st_field` | 10 |
| `cjp` | 12 |

## Jump relocation

The assembler resolves labels and writes function-local byte addresses into
jump operands. Destinations must be instruction starts in the same function;
the end of a function and bytes inside operands are invalid destinations.
Concatenating functions into an artifact does not change their jump addresses.

An absolute relocation supplies a function-local address. A relative relocation
is measured from immediately after the eight-byte address operand (before the
flags byte in `cjp`). Labels identify the start of an emitted `lbl` instruction;
label metadata itself adds no bytes. Missing or duplicate labels, invalid targets,
and legacy symbol relocations cause assembly diagnostics and no usable code.

Control-flow generation uses the shared `ArcRelocationLabel` and
`ArcRelocationTarget` models. `ArcRelocationLabel.Create()` creates a fresh label
identity; `ArcRelocationTarget.ForLabel(label)` creates a target for that identity.
The label is placed by attaching it to an `ArcControlFlowLabelInstruction`.
The assembler determines byte locations without mutating the source models.
